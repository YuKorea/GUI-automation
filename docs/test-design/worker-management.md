# 테스트 설계서 — 관리자 웹 · 작업자 관리

| 항목 | 내용 |
|------|------|
| 대상 | 리포지토리 관리자 웹 > 작업자 관리 (`/worker`) |
| 범위 | 작업자 생성, 조회·검색, 수정, 삭제, 승인 상태, 목록 페이징 |
| 제외 | 관리자 로그인 보안 정책, 다국어, 브라우저 호환성 (별도 계획) |
| 근거 | 화면 동작 관찰, 사용자 매뉴얼 7.6.2 작업자 메뉴 |
| 설계 기법 | 동등 분할(EP), 경계값 분석(BVA), 상태 전이, 오류 추측 |
| 자동화 | `tests/web/test_worker_crud.py` (아래 표의 "자동화" 열) |

---

## 1. 위험 기반 우선순위

기능별로 **실패했을 때의 영향**과 **발생 가능성**을 평가해 테스트 깊이를 정했습니다.

| 기능 | 영향 | 가능성 | 우선순위 | 근거 |
|------|------|------|------|------|
| 작업자 생성 | 높음 | 중간 | **P1** | 작업자가 없으면 클라이언트 로그인·공동 작업 불가 |
| 작업자 삭제 | 높음 | 중간 | **P1** | 잘못 삭제하면 그룹·작업 이력에 영향, 되돌리기 어려움 |
| 승인 상태 | 높음 | 낮음 | **P1** | 미승인 작업자의 접근 허용 시 권한 문제 |
| 검색·조회 | 중간 | 중간 | **P2** | 관리자가 대상을 못 찾으면 업무 지연 |
| 수정 | 중간 | 중간 | **P2** | 작업자명 오표시 |
| 목록 페이징 | 낮음 | 중간 | **P3** | 항목 누락처럼 보이는 혼란 |

P1은 정상·예외·경계를 모두 확인하고, P3는 대표 경로만 확인합니다.

---

## 2. 입력값 분석 (생성 팝업)

| 입력 | 유효 분할 | 무효 분할 | 경계값 |
|------|------|------|------|
| 아이디 (필수) | 영문 소문자·숫자 조합, 중복 없음 | 빈 값, 공백만, 기존 아이디와 중복 | 최소·최대 길이, 최대+1 ※ |
| 비밀번호 | 정책을 만족하는 값 | 빈 값 ※, 정책 미달 ※ | 최소 길이, 최소-1 ※ |
| 작업자명 | 한글·영문 | — | 최대 길이 ※ |

※ 요구사항 문서에 정의가 없어 **개발팀 확인이 필요한 항목**입니다 (5장).

## 3. 테스트 케이스

| WK-13 | P2 | 기능 | 검색 후 검색어 지우기 | 숨겨졌던 행이 다시 표시 | `test_search_reset` |

| WK-16 | P2 | 기능 | 작업자 수정 팝업 열기 | 기존 값이 채워진 팝업 표시 | `test_edit_popup_opens` |

## 4. 자동화 대상 선정 기준

| 기준 | 자동화 | 수동 |
|------|------|------|
| 회귀 때마다 반복되는가 | 생성·검색·삭제 기본 흐름 | 일회성 정책 확인 |
| 결과를 기계적으로 판정할 수 있는가 | 행 개수, 상태 텍스트 | 안내 문구의 적절성 |
| 데이터를 스스로 만들고 지울 수 있는가 | 테스트용 작업자 | 그룹에 묶인 작업자 (다른 데이터에 영향) |
| 외부 시스템이 필요한가 | 아니오 | 데스크톱 클라이언트 로그인 (WK-10) |

---

## 5. 개발팀 확인 요청 (요구사항 질의)

테스트 설계 중 정의되지 않은 동작을 발견해 확인을 요청한 항목입니다.

1. 아이디 허용 문자와 길이 제한, 앞뒤 공백 처리 (WK-04, WK-05)
2. 비밀번호 정책 (최소 길이, 조합 규칙, 빈 값 허용 여부) (WK-06)
3. 승인 상태 변경 시 이미 로그인한 클라이언트 세션 처리 (WK-10)
4. 그룹에 속한 작업자 삭제 시 동작 — 연쇄 삭제인지 차단인지 (WK-20)
5. 검색의 대소문자 구분 여부 (WK-14)

---

## 6. 테스트 데이터 원칙

- 자동화 테스트는 `qa_<타임스탬프>` 형식의 작업자를 직접 만들고, 끝나면 삭제합니다.
- 기존 계정은 조회 외에 변경하지 않습니다.
- 접속 정보는 `.env`에만 두고 저장소에 올리지 않습니다.
