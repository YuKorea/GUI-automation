# Mattermost 웹 테스트 계획서

| 항목 | 내용 |
|------|------|
| 대상 | Mattermost Team Edition 12.1.0 (Docker `mattermost/mattermost-preview`) |
| 환경 | 로컬 Docker (`http://localhost:8065`), 브라우저 Chromium / Firefox / WebKit |
| 작성일 | 2026-11-26 |
| 상태 | 1주차: 인증·권한 범위 작성 및 자동화 완료 |

> 모든 테스트는 내 PC나 CI에 띄운 서버에서만 실행합니다. 공식 커뮤니티 서버 등 운영 중인 서버에는 실행하지 않습니다.

---

## 1. 목적

사내 메신저에서 사용자가 가장 크게 피해를 보는 문제는 **로그인이 안 되는 것**, **권한 없는 사람이 정보에 접근하는 것**, **메시지가 사라지거나 다른 사람에게 가는 것**입니다. 이 세 가지를 위험 기반으로 우선 검증하고, 반복 확인이 필요한 항목은 자동화해서 변경 때마다 회귀를 확인합니다.

## 2. 범위

### 포함

| 영역 | 내용 | 일정 |
|------|------|------|
| 인증 | 로그인 / 실패 / 로그아웃 / 세션 토큰 | 1주차 ✅ |
| 권한 | 시스템 관리자 vs 일반 사용자, 공개 가입 차단 | 1주차 ✅, 3주차 확장 |
| 채널 | 공개·비공개 채널 생성, 가입, 나가기, 비공개 채널 접근 차단 | 2~3주차 |
| 메시지 | 작성, 수정, 삭제, 스레드 답글, 멘션 | 2~3주차 |
| 파일 | 첨부 업로드, 크기·형식 제한 | 4주차 |
| 실시간 | 다른 사용자가 보낸 메시지가 새로고침 없이 표시 | 4주차 |
| 크로스 브라우저 | 핵심 흐름(smoke)을 Chromium / Firefox / WebKit에서 | 5주차 |

### 제외 (이유)

| 항목 | 제외 이유 |
|------|-----------|
| 성능·부하 테스트 | 로컬 단일 컨테이너라 결과가 실제 운영 성능을 대표하지 못함 |
| 모바일·데스크톱 앱 | 이번 범위는 웹 클라이언트. 모바일 뷰포트 표시만 5주차에 확인 |
| SSO / LDAP / SAML | Enterprise 기능이며 외부 인증 서버가 필요 |
| 플러그인, 통합(웹훅·봇) | 핵심 기능 이후 여유가 있으면 추가 |
| 운영 서버 대상 보안 진단 | 허가되지 않은 대상이므로 하지 않음 |

## 3. 위험 기반 우선순위

위험도 = 영향도(1~3) × 발생 가능성(1~3). 6 이상은 P1으로 보고 자동화를 먼저 합니다.

| ID | 위험 | 영향 | 가능성 | 위험도 | 우선순위 |
|----|------|:---:|:---:|:---:|:---:|
| R1 | 정상 사용자가 로그인하지 못함 | 3 | 2 | 6 | P1 |
| R2 | 일반 사용자가 관리자 기능·설정에 접근 | 3 | 2 | 6 | P1 |
| R3 | 로그아웃 후에도 세션 토큰이 유효함 | 3 | 2 | 6 | P1 |
| R4 | 비공개 채널 메시지를 비회원이 읽음 | 3 | 2 | 6 | P1 |
| R5 | 메시지 전송 실패·유실 | 3 | 2 | 6 | P1 |
| R6 | 로그인 오류 메시지로 계정 존재 여부 노출 | 2 | 2 | 4 | P2 |
| R7 | 메시지 수정·삭제가 다른 사용자 화면에 반영 안 됨 | 2 | 2 | 4 | P2 |
| R8 | 허용되지 않은 파일 형식·크기 업로드 | 2 | 2 | 4 | P2 |
| R9 | 특정 브라우저에서만 레이아웃·입력 오류 | 2 | 1 | 2 | P3 |

## 4. 테스트 레벨과 자동화 기준

| 레벨 | 무엇을 | 왜 |
|------|--------|----|
| API (pytest + requests) | 상태 코드, 응답 스키마, 권한 규칙, 부정 케이스 | 빠르고(1건 수십 ms) 안정적. 서버 규칙은 여기서 촘촘히 |
| E2E (Playwright + POM) | 사용자가 보는 화면 흐름, 오류 표시, 화면 이동 | 느리고 깨지기 쉬우므로 핵심 흐름만 |
| 수동 탐색 | 새 기능 첫 확인, 사용성, 문구 | 자동화 전에 무엇을 테스트할지 찾는 단계 |

**자동화 대상 선정 기준**: (1) P1·P2 위험 (2) 릴리스마다 반복 확인 (3) 결과를 기계적으로 판단 가능. 셋 중 두 개 이상이면 자동화합니다.

**테스트 데이터**: 사용자·팀은 `scripts/seed.py`가 API로 만듭니다(멱등). UI로 데이터를 준비하지 않습니다.

## 5. 테스트 케이스 (1주차)

설계 기법: EP = 동등 분할, BVA = 경계값 분석, ST = 상태 전이, NEG = 부정 테스트

| TC ID | 위험 | 레벨 | 설계 | 시나리오 | 기대 결과 | 자동화 |
|-------|------|------|------|----------|-----------|--------|
| AUTH-01 | R1 | API | EP(유효) | 올바른 아이디·비밀번호로 로그인 | 200, `Token` 헤더, 사용자 스키마 일치, 비밀번호 필드 없음 | ✅ `test_auth_01` |
| AUTH-02 | R1 | API | EP(무효)·BVA | 틀린 비밀번호 / 없는 사용자 / 빈 비밀번호 | 401(또는 400), 토큰 없음, 오류 스키마 일치 | ✅ `test_auth_02` ×3 |
| AUTH-03 | R6 | API | NEG | 없는 사용자와 틀린 비밀번호의 응답 비교 | 상태 코드·메시지가 같음 | ✅ `test_auth_03` |
| AUTH-04 | R3 | API | NEG | 토큰 없이 `/users/me` 호출 | 401 | ✅ `test_auth_04` |
| AUTH-05 | R3 | API | ST | 로그인 → 로그아웃 → 옛 토큰으로 호출 | 401 (세션이 서버에서 폐기됨) | ✅ `test_auth_05` |
| PERM-01 | R2 | API | NEG | 일반 사용자가 `/config` (관리자 전용) 호출 | 403 | ✅ `test_perm_01` |
| PERM-02 | R2 | API | EP | 관리자가 같은 API 호출 (PERM-01의 대조군) | 200 | ✅ `test_perm_02` |
| PERM-03 | R2 | API | NEG | 비로그인 상태로 회원가입 API 호출 | 403 `no_open_server` | ✅ `test_perm_03` |
| AUTH-E2E-01 | R1 | E2E | EP | 화면에서 로그인 | 팀 기본 채널(town-square)로 이동, 입력창 표시 | ✅ |
| AUTH-E2E-02 | R1 | E2E | EP(무효) | 틀린 비밀번호로 로그인 | 오류 배너 표시, 로그인 화면 유지, 아이디 입력값 유지 | ✅ |
| AUTH-E2E-03 | R3 | E2E | ST | 로그인 → 로그아웃 → 채널 URL 직접 접근 | 로그인 화면으로 이동 | ✅ |

## 6. 진입·종료 기준

- **진입**: 서버 `/api/v4/system/ping`이 `OK`, 시드 완료
- **종료**: P1 TC 100% 통과, P2 이상 미해결 결함 0건 또는 리포트 후 합의, 같은 코드로 3회 연속 실행해 결과가 같음(흔들림 없음)

## 7. 결함 관리

- 심각도: Critical(서비스 사용 불가·보안) / Major(핵심 기능 오류) / Minor(우회 가능) / Trivial(문구·표시)
- 리포트 형식: 환경, 재현 단계, 기대 결과, 실제 결과, 증거(스크린샷·응답 본문), 심각도
- 실제 결함으로 확인되면 Mattermost GitHub 저장소에 이슈로 보고하고 링크를 `docs/bug-reports/`에 남깁니다.

## 8. 1주차에 발견한 것 (테스트 설계에 반영)

| 발견 | 내용 | 반영 |
|------|------|------|
| 첫 사용자 이후 공개 가입 차단 | 시드 작성 중 비로그인 `POST /users`가 403 `no_open_server`를 돌려줌 | 기대 동작이므로 PERM-03으로 회귀 테스트 고정. 시드는 "관리자 로그인 → 관리자 권한으로 사용자 생성" 순서로 변경 |
| 온보딩 체크리스트가 클릭을 가로챔 | 일반 사용자 첫 로그인 시 오버레이가 계정 메뉴 클릭을 막아 AUTH-E2E-03 실패 | 결함 아님(의도된 안내 UI). 테스트 대상이 아니므로 시드에서 사용자 설정으로 끔 |
| 데스크톱 앱 안내 화면 | 첫 방문 시 `/landing`으로 이동 | 사용자가 "브라우저로 보기"를 누를 때 남는 localStorage 값을 테스트 시작 전에 넣음 |
